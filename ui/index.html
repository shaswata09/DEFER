Where Rules End and Judges Begin

Measuring the judgment boundary in multi-agent systems security: how much of the decision to allow an agent's action can deterministic checks make, and how much needs an LLM judge?

Paper (arXiv:2610.07657) Code Dataset Cite

Reported runs: Qwen3-235B primary, four domains, 75 attack variants per domain × 3 trials; JudgeOnly and DEFER judged by the four-judge open-weight panel Local4 (3 of 4), re-adjudicated offline from the logged inputs. Every number on this page is computed in the browser from the per-trial outcomes in the dataset.

1 · Problem

Pipelines that compose MAS defenses leave the final verdict to an LLM judge. How much of that verdict actually requires judgment?

LLM-based multi-agent systems invoke tools, share memory and delegate tasks, and each interaction may carry adversarial content. Existing defenses are designed and evaluated one attack class or channel at a time. When they are combined, the decision is commonly delegated to a judge, which requires no policy engineering and can reason about intent, but is costly, hard to audit, and can be attacked through the very content it reads.

We organize established defenses into five principles over the two surfaces through which untrusted content enters a MAS, implement them as a cascade that denies what it can deterministically and defers the rest to a judge panel, and measure where the boundary between rules and judges lies.

Where untrusted content enters

Two surfaces: the tool-orchestration surface (every agent-to-tool call and every message between agents passes through the host) and the memory-management surface (every read and write to a shared store passes through a memory gateway). Five channels carry attacker content onto them.

Threat model

T1, content attacker: controls data reaching agents through C1–C3, such as a crafted log line, a poisoned sandbox verdict or a planted memory record. Cannot modify code, configuration, weights or the network.

T2, compromised agent: additionally controls what one agent emits, its handoffs (C4) and its proposal rationales (C5). AP-15 adds infrastructure faults.

The attacker knows the system's purpose and tool names but not the defense rules, and does not adapt to feedback. A defense-aware, adaptive attacker is out of scope, so the results are an upper bound on the deterministic tier's security.

Goals: (G1) no tool call outside the calling phase's manifest executes; (G2) no state-changing action executes unless the incident's evidence supports it; (G3) no poisoned or fabricated record persists in a shared store; (G4) no agent receives memory content outside its clearance.

2 · Defense

DEFER: DEterministic-First Enforcement with Residual judgment

Twenty-eight checks in cascade order. Every check fails closed: a denial stops the remaining calls in that phase and surfaces the proposal for human review, and a validator error counts as a rejection. Only consequential proposals that no rule decides reach the panel. The mechanisms are adopted versions of published defenses; the contribution is the ordering and the measurement.

The cascade

All 28 checks

Thresholds as frozen for the reported runs (paper, Table “All checks”). Types: I content-independent rule (never reads what a proposal says, so rewording cannot pass it), C content-dependent rule, E similarity threshold over embeddings, L LLM judgment; S marks a check that keeps state across incidents.

3 · Testbed and method

A host-mediated, four-phase MAS in four domains

Monitor triages an incoming incident, Analyze investigates it with tools and prior incidents, Admin proposes actions that P3 verifies, and Report writes an after-action record to memory. A domain is defined entirely by declarative configuration (tool registry and stubs, phase manifests, parameter rules, memory schemas, access policy, sensitive-content patterns, seed data); the enforcement code is identical in all four. Thresholds, pattern lists and the judges' prompt were set while configuring CyberOps and tuned on none of the others, so healthcare, finance and legal show how the same defense behaves on content it was not tuned for.

Domains

Configurations

Four arms probe the boundary directly: judge everything after rules, a permissive gate, rule-evading siblings (variants rewritten to satisfy the rule that stopped them), and judged writes.

Oracle and metrics

One oracle scores every configuration from the logs. Each variant declares its harmful effects (a tool executed with matching arguments, a canary persisted, delivered unsanitized or sent outbound, an ordered chain, an approved proposal carrying a canary, a read the phase is not entitled to); it never asks whether a particular defense fired. A trial is not attempted, blocked or executed.

ASR = executed / total. Attempt rate = (blocked + executed) / total. Block | attempt = blocked / attempted. Benign denied = denied / proposed tool calls in benign incidents. First interception: the check that first denied a matching proposal, and its tier. Intervals are 95% cluster-bootstrap over variants.

Models

Primary agents: Qwen3-235B-A22B-Instruct in all four domains; gpt-oss-120b and Llama-3.1-8B through every configuration in CyberOps (temperature 0.7, logged seed). Judges: Local4, Mistral-Small-3.2-24B, Gemma-4-31B-it, gpt-oss-120b and Llama-4-Scout, four lineages chosen before any result was seen, quorum 3 of 4; a model never judges its own proposals.

Attack paths

The 35 inventory vectors are grouped into 15 attack paths by shared objective and injection point. Each has five hand-written variants per domain (AP-4 seven, AP-15 three): 75 per domain, 300 in total. Every adversarial string carries an attacker-chosen canary so that its effects can be traced mechanically; attack descriptions live in a metadata block no model sees. Benign companions: 35 scenarios (20 in CyberOps, five in each other domain) exercise the same tools, stores and consequential actions as the attacks, including legitimate containment of genuinely malicious activity.

6 · Findings

The boundary has a clear shape

Rules decide attacks that must violate a statable property, judges decide attacks that misstate only intent, and plausible fabricated records evade both.

  1. State the policy, and put the judges last. With the same four judges, the rules take attack success from to in CyberOps, and judging everything the rules pass changes no outcome. Where a policy or a ledger can state what an attack must break, the judges mainly release legitimate work no rule can clear (about 46 points of it in CyberOps); where an attack stays within policy, as most third-party attacks do, they carry the defense.
  2. Approve by classifying the action, not by scoring its context. Deterministic approval is safe when a consequentiality table lets non-consequential calls through; no attack used that path. Approval by a risk score is anti-selective: a gate keyed on scope and proportionality approves 84% of the attack proposals it sees but only 36% of legitimate ones, because attacks are small, reversible and targeted, and the scores come from evidence the attacker shapes.
  3. Rule evasion is a hand-off, not a bypass. Rewriting the 24 variants that the evidence-similarity rules stopped so that they satisfy those rules moved the decision to the judges, who with the remaining rules held 19 of 24. The adversary's real target is the judge.
  4. Judges need diversity and do not transfer. A same-lineage panel of three was 3.5 times weaker than its single member, and one judge approved 67% of attack proposals. The panel that approves 96.3% of legitimate proposals in CyberOps, where its prompt was written, approves 36.8% in legal: the central limit of the approach is judgment, not the deterministic tier.
  5. Plausible writes defeat rules and judges alike. A fabricated legal precedent passes every write check, and judges approve it in 5 of the 8 judged writes. Inspection cannot catch a record that is wrong but plausible; provenance of what tools return is the remaining lever.
  6. Let state expire. Replay detection keyed on an action's shape and ledgers that never expire deny 88% of routine consequential work over twenty incidents; a one-incident window removes most of these denials, and stateful defenses need evaluation in persistent mode too.
  7. Log what the judges see. Logging every judge input makes any panel re-evaluable offline, which is how panels were compared on identical decisions and how every number here is reproduced without a GPU.

Scope and limitations

Static attacks. The boundary is measured under static attacks; an adaptive attacker is outside the problem statement, so the numbers are an upper bound on the deterministic tier's security. The rule-evading siblings are the one rewording probe. Replay. Panel results are re-adjudicated decisions; a changed decision cannot regenerate the proposals that would have followed, though a live calibration agrees within a point.

Baselines. No external defense such as Progent or CaMeL was run on the suite, and frontier judges ran only in the judged-write arm. Coverage and realism. Tools are stubs, memory is synthetic, and the four domains share one skeleton; 35 benign scenarios bound every cost estimate; each attack path has at most 21 trials per configuration and domain, so per-path differences are descriptive.

7 · Dataset

Attack suite, benign scenarios and per-trial outcomes

The released dataset contains the 300 attack variants (plus the 24 rule-evading siblings) and 35 benign scenarios exactly as the harness delivers them, the per-trial outcomes of every reported run, the raw per-trial logs, and every cached judge vote. Payloads are prompt-injection strings, poisoned records and forged tool responses that target the stub environment and carry canary values; they contain no working exploit against any real product.

8 · Reproduce and cite

Regenerate every table and figure

No GPU and no API are needed: tables and figures are rebuilt from the logs and the cached judge votes.

git clone https://github.com/shaswata09/DEFER
cd DEFER && ./install.sh
make reported      # the reported boundary, ablation, judged fractions
make figures       # every paper figure
make test          # the test suite
python -m ui.build_data --check   # this page's data

Running new trials requires the vLLM-served models listed in the paper's serving appendix; the README's reproduction guide lists wall-clock time and cost per experiment.
